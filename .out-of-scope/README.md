# Out of scope

Store: committed

Each file here is one capability this project was asked for and decided not to build, with the
reason that decision holds and the requests that asked for it. It exists so the same request is
answered from the decision already taken, instead of being argued again.

**Read it before proposing a feature, and before triaging a request.** A request that matches a
concept here — by meaning, not by wording — is answered from the matching file: the decision, the
reason, and the question of whether it still holds.

**Only a refusal lands here.** Something out of the current release but planned is a ticket, and a
capability that already exists is pointed to, not recorded. An effort's own scope boundary stays in
its plan.

**How a file is written.** The triage pass writes and updates these files, one per concept: a short
design note saying what was refused, why, and each request that asked for it. Changing our mind
removes or rewrites the file, with the reason.

This store is committed, so everyone working in the repo reads the same decisions.
